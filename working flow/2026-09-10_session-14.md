## Results

**Task 1.6 — PASS.** Flow / router / `or_` / `and_` / crew-from-Flow verified
against `1.15.20`.

### API

- Imports present: `Flow`, `listen`, `start`, `router`, `or_`, `and_` from
  `crewai.flow.flow`. `Flow` is generic (`Flow[StateModel]`).
- `start(condition=None)`, `listen(condition)`, `router(condition=None, *, emit=None)`,
  `or_(*triggers)`, `and_(*triggers)`.
- `Flow.kickoff(self, inputs=None, input_files=None, from_checkpoint=None,
  restore_from_state_id=None)`.

### Experiment A — typed state model

- `Flow[StateA]` accepted. `flow.state` is
  `StateWithId(FlowState → StateA → BaseModel)` — `isinstance(flow.state, StateA)` is
  **True** (Flow wraps the model and adds an `id` field).
- State is **mutable through the execution path**: `counter` 0 → 1 (`seed`) → 11
  (`bump`); `trail == ['seed', 'bump']`.
- `kickoff(inputs={"seed_value": "INJECTED_A"})` → `flow.state.seed_value ==
  'INJECTED_A'` (inputs merged into state).
- Final state observable via `flow.state`. `kickoff()` returned `'counter=11'` — the
  return value of the last leaf method.

### Experiment B — @start → @listen → @listen

Event order `['n1', 'n2', 'n3']` — deterministic.

### Experiment C — @router

- `which="A"` → `state.ran == ['begin', 'on_a']` (only `on_a`).
- `which="B"` → `state.ran == ['begin', 'on_b']` (only `on_b`).
- The router method **returns a plain string label**; `@listen("ROUTE_A")` /
  `@listen("ROUTE_B")` consume it. The unmatched listener does not execute.

### Experiment D — or_ / and_

- `@listen(or_(p1, p2))` with two `@start` triggers: `joined_or` fired **once** — as
  soon as the **first** trigger completed; it was **not** re-fired when the second
  completed. Events: `['p1', 'p2', 'joined_or']`.
- `@listen(and_(q1, q2))`: `joined_and` fired **once**, only **after both** q1 and q2.
  Events: `['q1', 'q2', 'joined_and']`.

### Experiment E — Crew.kickoff(inputs=...) from inside a Flow method

- `crew.kickoff(inputs={"topic": self.state.topic})` inside a `@start` method
  **succeeded**.
- Inputs arrived: the interpolated `{topic}` value `SPIKE_TOPIC_42` appeared in the
  crew's prompt (`inputs reached the Crew: True`).
- Result returned to the Flow: `str(out) == '{"echo": "handled"}'` (a `CrewOutput`),
  stored in `state.crew_said`.
- The Flow **continued** past the crew call: the downstream `@listen(run_crew)` ran
  (`state.after == True`); `kickoff()` returned `'flow-continued'`.

### Experiment F — failure behaviour

- **Unlistened router label:** `@router` returns `"NOBODY_LISTENS_HERE"` with no
  matching `@listen` → `kickoff()` **returns that label**, the Flow ends **quietly**,
  no downstream method runs, **no exception**. (Design consequence: a router must only
  emit labels that have listeners, or the pipeline silently stops.)
- **A Flow node raises:** `@start` raising `RuntimeError` → the exception **propagates
  out of `kickoff()`** as `builtins.RuntimeError` (original type); the downstream
  `@listen` does **not** run.

### Task 1.6 conclusion (as required)

- Flow runtime verified: **YES**
- typed state verified: **YES** (`Flow[StateModel]`, mutable, observable; wrapped as
  `StateWithId`)
- router verified: **YES** (string-label routing; only the matched listener runs)
- `or_` / `and_` verified: **YES** (`or_` fires on first trigger, once; `and_` fires
  once after all)
- `Crew.kickoff` from Flow verified: **YES** (inputs in, `CrewOutput` out, Flow
  continues)
- deviations from `PROJECT_PLAN.md` §H assumptions: **none**. Two behaviours to design
  around, not deviations: (1) an unlistened router label stops the Flow silently;
  (2) a raising node aborts the Flow with the original exception (Phase 8 must catch and
  map to `status="halted_*"`).

### Proven vs inferred

- *Proven by execution:* typed mutable observable state; `@start`/`@listen` ordering;
  `@router` string-label routing with single-branch execution; `or_` single fire on
  first trigger; `and_` single fire after all; `Crew.kickoff(inputs=...)` from a Flow
  method with inputs in / result out / Flow continuation; silent stop on unlistened
  label; exception propagation on a raising node.
- *Inferred from source only:* `@persist` / checkpoint behaviour (Plan §V.2 N9: not
  used); `kickoff_async` / `astream`; `flow.plot()` output (not exercised);
