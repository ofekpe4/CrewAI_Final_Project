## Architectural Decisions

1. **The fix generalizes Session 25's identifier-specific emphasis into an
   explicit, ordered, three-step process covering every column name** —
   not a broader rewrite, not a schema/code change. *Why:* Session 25's
   own diagnosis was precise: repeated, concrete emphasis worked for the
   identifier; a single general sentence did not generalize to other
   columns. The fix targets exactly that gap with the same technique
   (explicit steps + concrete forbidden-pattern examples) applied to the
   general case, not a new mechanism.
2. **`context=[inspect_task, eda_task]` needed no code change** to make
   STEP 1 ("read the accepted CleaningPlan") possible — Task 3 already
   receives Task 1's raw output as prior context (Pattern A wiring,
   unchanged since Session 23). The fix only had to tell the agent to
   actually use it that way.
3. **The `customer_id` test assertion was tightened, not removed**, when
   STEP 3's concrete negative example legitimately needed to name it once.
   *Why:* the ORIGINAL protective intent (never assert `customer_id` as if
   it were correct) is preserved exactly — a single occurrence inside an
   explicit "do NOT invent" clause serves that same intent, it doesn't
   violate it; weakening the test to just delete the check would have lost
   real protection.
