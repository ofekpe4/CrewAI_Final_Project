## Architectural Decisions

Full reasoning lives in `PROJECT_PLAN.md`. The decisions most likely to be needed early:

- **Streamlit over Flask** (Plan §M). This is an artifact-driven workflow, not a CRUD app.
  The hard UI problem is live pipeline status + streaming logs; Streamlit solves it with
  `st.status()`, Flask would need a background worker plus polling for no added value.
- **Contract separates `observed` from `constraints`** (Plan §E.2). Descriptive statistics
  are never auto-promoted to hard business rules. Every enforced constraint carries a
  `justification`. This prevents false failures on legitimate future values.
- **No invented semantic metadata** (Plan §J). Currency is declared only if the source
  documents it; otherwise `unit: currency_unspecified`. The failure demo is therefore framed
  as a **scale change** (×100), which is defensible without knowing the currency.
- **Fault injection sits inside the Flow, between Crew 1 and the gate** (Plan §P.1). The
  earlier design — corrupt the file, then rerun the whole pipeline — was logically broken:
  Crew 1 would regenerate the file and erase the corruption before the gate saw it.
- **Critical agents fail visibly; only narrative agents get fallbacks** (Plan §D, §G).
  A pipeline that looks successful because a fallback quietly replaced a critical decision
  is the exact failure mode this project exists to prevent.
- **CrewAI orchestration pattern is not yet decided** (Plan §C.2). Pattern A (one kickoff,
  `Task(guardrail=…, callback=…, output_pydantic=…)`) versus Pattern B (staged kickoffs with
  Python between them). A technical spike decides this before any crew code is written.
- **Dependency graph has two parallel tracks** (Plan §T.0). The deterministic track
  (dataset → contract → gate → tools) does not depend on the CrewAI spike. The agentic track
  (Crew 1 → Crew 2 → Flow) is hard-blocked by it.
