## Architectural Decisions

1. **Two ways to build a scenario's starting handoff — real artifacts by
   default, the Phase 3/4 fixture only where the real contract cannot
   express the scenario.** The real production `dataset_contract.json`'s
   `required_features` lists every non-key, non-target column (no
   unreferenced column exists for `contract_only_change`) and declares no
   `target.drift` policy (needed by `flip_target_encoding`). Using the
   synthetic fixture for exactly those two scenarios — and the real,
   live-verified artifacts for the other eight — maximizes realism without
   inventing contract fields the real pipeline never produced.
2. **`change_dtype`'s test casts to `int64`, not `str`.** Casting a
   numeric column to `str` in memory does not survive a CSV round-trip —
   `pandas.read_csv` re-infers numeric-looking strings back to `float64`,
   silently defeating the scenario. Matches the existing, already-proven
   convention in `tests/unit/test_validator_schema.py::
   test_incompatible_dtype_change_is_a_schema_error`.
3. **The `unknown_category` "no declared domain" companion case asserts
   absence of one specific finding, not an overall PASS.** Any byte-level
   CSV edit trips `INTEGRITY_SHA256_MATCH` (the contract's hash was
   computed against the original bytes) regardless of which column
   changed or why — that is correct, unrelated behavior, not something
   this scenario should suppress by picking an artificially "free" edit.
   The one thing worth proving is that `CONSTRAINTS_CLOSED_DOMAIN`
   specifically never fires for a column with no declared closed domain.
4. **No live, billed `make demo-fail` run this session.** The zero-cost
   `--replay-plans --inject-failure scale_change` CLI invocation (§7)
   exercises the identical production code path — real dataset, real
   stored Crew 1 plan, real fault injection, real gate — with the only
   difference being a replayed vs. a freshly-called Crew 1. Phase 8's
   existing live acceptance run already proves the successful path end to
   end. Spending real `OPENAI_API_KEY` budget on a second live
   demonstration is the user's call, not a default action — flagged as
   Manual Action Required in the final report rather than executed
   unilaterally.
5. **No browser automation (Playwright/Selenium/claude-in-chrome) for
   screenshots**, matching the explicit instruction. Gate 10.6's
   behavioral verification was done entirely through the existing,
   already-proven `AppTest`-based smoke suite; actual screenshot capture
   is left as a manual, documented action (see Manual Action Required).
