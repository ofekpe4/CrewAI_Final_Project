### 3 — Pipeline-run integration (Internal Gate 9.4)

`lib/pipeline_runner.py`: `build_command(mode, fault_injection)` maps a
closed `{"normal","validate_only","replay_plans"}` mode plus an optional
`"scale_change"` fault onto the exact fixed argv `[sys.executable,
"scripts/run_pipeline.py", ...]` — raises `InvalidRunRequest` (before
spawning anything) for any other input, and specifically rejects
`fault_injection` combined with `validate_only` (mirroring
`scripts/run_pipeline.py`'s own `argparse` rejection). `stream_pipeline_run`
runs it via `subprocess.Popen(cmd, shell=False, ...)` — never `os.system`,
never a shell string — and yields stdout/stderr lines live for `st.status()`
plus a final `__EXIT_CODE__:<n>` sentinel. Page 1 never claims a stage
completed ahead of the real process; after the process exits it calls
`st.rerun()` so `run_summary.json`/`run_metadata.json`/artifacts are
reloaded fresh. Fault injection is an explicit, off-by-default checkbox
inside a collapsed "Demo controls" expander, never defaulted on.

## Architectural Decisions

1. **`streamlit==1.64.0`, not the first version tried (`1.50.0`).** `pip
   install streamlit==1.50.0` silently downgraded the pinned `pandas` from
   `3.0.5` to `2.3.3` (its own dependency spec is `pandas<3`). Rejected
   specifically because §R.1's reproducibility promise names `pandas` as one
   of the version-pinned guarantees — silently letting an unrelated UI
   dependency downgrade it would have quietly broken that promise. `1.64.0`
   declares `pandas<4,>=1.4.0`, compatible with the existing pin; verified
   the installed `pandas` stayed at exactly `3.0.5` and the full regression
   suite stayed green.
2. **Multipage app via the `app/pages/` auto-discovery convention, not
   `st.navigation`/`st.Page`.** The Plan's own Internal Gate 9.1 file tree
   already specifies numbered files under `pages/` — the simplest mechanism
   that satisfies it directly, with zero extra configuration.
3. **The Run button uses a fixed-argv `subprocess.Popen`, never an in-
   process `HarborValeFlow()` call.** Importing/instantiating the Flow
   directly inside the Streamlit process would pull `crewai`'s full runtime
   into every page load and make one long-running pipeline call block (or
   need to be threaded inside) the same process serving the UI. The Plan's
   own §M explicitly names this as the "preferred" integration when a
   reusable in-process runner isn't already exposed, and it keeps the UI
   process a pure, fast-reloading presentation layer.
4. **`st.iframe` instead of `st.components.v1.html` for `eda_report.html`.**
   Discovered live, not from documentation lookup: loading any page that
   embeds the report printed a real runtime deprecation warning stating
   removal "after 2026-06-01" — already past on the current date
   (2026-09-24). Switched immediately rather than shipping a page that logs
   a stale-dated deprecation warning on every load.
5. **Smoke tests follow the project's existing no-`pytest` convention
   exactly**, rather than introducing `pytest` as a new dev dependency for
   this phase alone — consistent with README's own documented state
   ("`pytest` is not installed yet") and with not expanding scope beyond
   the approved task.
6. **Artifact-path isolation in tests patches `app.lib.ui_helpers`'s own
   re-exported constants, never `harbor_vale.io_paths` itself.** Keeps the
   isolation local to UI code under this phase's control; leaves the
   pipeline's own path layer completely untouched by UI tests.
