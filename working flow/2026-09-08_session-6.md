## Architectural Decisions

- **`io_paths.PROJECT_ROOT` derived, not configured.** Matches the Plan §L snippet
  verbatim (`Path(__file__).resolve().parents[2]`). `settings.yaml` deliberately contains
  **no** filesystem paths — a single authority (§L "כל נתיב במערכת עובר מכאן").
- **`config/` is a real package** (`__init__.py`) so tests import `config.llm`
  unambiguously, rather than manipulating `sys.path` to import a bare `llm`. `config/llm`
  importing `harbor_vale.io_paths` for `SETTINGS_YAML` is intentional: the path layer
  stays the one source of path truth.
- **`__init__.py` added now, not in Task 0.7.** Task 0.7 was "directory skeleton" and the
  Plan §L does not itemise `__init__.py`; they become necessary the moment real modules
  need importing, which is now. Minimal (docstring only), no `__version__` to avoid
  maintenance.
- **`conftest.py` instead of `pyproject.toml`/editable install.** The task forbids
  environment changes; `conftest.py` gives pytest import resolution with zero install.
  `pyproject.toml` remains deferred.
- **Tests are dual-mode (pytest + `__main__`).** Plan §O standardises on pytest, but
  pytest is not installed yet (dev dependency, deferred with `requirements-dev.txt` in
  Task 0.5). Writing them pytest-style keeps them correct for later; the `__main__`
  runner and the avoidance of fixtures let them be *actually executed and verified now*.
- **`business_context` kept provisional.** Locking dataset semantics here would violate
  §A.7. The block is present (so the shape exists) but flagged `status: provisional`.
- No deviation from `PROJECT_PLAN.md` architecture was made or proposed.
