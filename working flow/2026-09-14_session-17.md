## Architectural Decisions

1. **No circular Phase 3→Phase 5 dependency.** PROJECT_PLAN.md §Phase 3's own
   scope line ("Pydantic + pandas בלבד") confirms no dependency on Crew
   1/cleaning. A synthetic, clearly-labeled fixture stands in for a cleaned
   CSV; nothing here reads, writes, or references
   `artifacts/crew1/clean_data.csv`.
2. **`ContractDraft`'s per-column shape mirrors the final schema's full
   `constraints` shape** (including `dtype` and a full `scale_drift`
   object), even though §D.3 point 6's summary list only explicitly names
   `semantic_type`/`unit`/`nullable`/`closed_domain`/`business_range`/
   `scale_sensitive`. *Why:* the worked §E.2 JSON example shows agent-
   authored justifications for exactly these additional fields (e.g.
   `dtype.justification: "continuous monetary amount"`,
   `scale_drift.justification: "this column is scale-sensitive; ..."`) —
   narrative reasoning only an agent/human would write, not something
   Python measures. Treating §D.3's list as a summary rather than
   exhaustive, and the worked example as authoritative for shape, avoids
   inventing a bare `scale_sensitive: bool` that the *builder* would then
   have to expand into a tolerance using a project-wide default — which
   would smuggle a semantic policy choice into "measured" Python code
   (§E.1 rule 6). This interpretation is recorded here explicitly, per this
   session's instruction to stop rather than silently resolve real
   ambiguity — it is not a Plan contradiction, just an underspecified
   summary list resolved in favor of the fully worked example.
3. **`columns` covers every column except the target**, with the target
   getting its own top-level section. *Why:* the target's `observed`/
   `constraints` shapes are genuinely different (positive rate + class
   counts vs. min/max/median; dtype/domain/nullable vs. a business range) —
   forcing it into the generic per-column shape would mean fields that don't
   apply to it either way.
4. **`dataset_name`, `source_documentation_url`, `contract_version`,
   `created_at`, `created_by`, `run_id` are excluded from `ContractDraft`
   entirely** — deterministic metadata the builder already knows, per §E.1
   rule 5 ("מדיד מעל מוצהר"). Giving the draft a chance to declare (and
   disagree with) them would only create a spurious authority conflict.
5. **A ≤50-distinct-values threshold gates whether a categorical column's
   `observed.value_distribution` is populated.** A deterministic, documented
   Python threshold (not a per-dataset judgement) — recording per-value
   shares for a near-identifier column is noise, not signal.
6. **The `Tuple[bool, Any]` guardrail-annotation finding is an addendum to
   `docs/architecture.md`, not a rewrite.** *Why:* it refines, not
   contradicts, the Phase 1 PEP 563 finding — Phase 1's spike guardrails
   were never constructed as real `Task` objects with this exact typing
   style, so the gap was never exercised until this session wired a
   guardrail into an actual `Task(...)` for the first time.
