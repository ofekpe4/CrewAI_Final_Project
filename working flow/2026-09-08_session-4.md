## Architectural Decisions

- **Root/baseline commit goes on `main`; feature work goes on `feature/project-foundation`.**
  Plan §N.1 says never commit directly to `main` for development, and Plan §N wants PRs
  merging into a green `main`. A repository still needs one root commit to make `main`
  exist as a merge target. The chosen split treats the root commit as the *repository
  baseline* (plan + instructions + lock + session history — all pre-existing, read-only
  reference material), and immediately branches so that every actual Phase 0
  implementation change lands on the feature branch and reaches `main` only via a
  reviewed merge. This honours the intent of §N.1 without leaving `main` uncreated.
- **No GitHub remote created.** Repo visibility (public vs private) is Plan §V.1 B7, still
  an open decision that is the user's to make, and the session scope is local Git
  foundation only. `git remote` is deliberately empty.
- **`.gitignore` kept to the Plan's §N.6 list** (plus obvious groupings/comments), not
  expanded with speculative entries — consistent with the Plan's anti-over-engineering
  stance.
