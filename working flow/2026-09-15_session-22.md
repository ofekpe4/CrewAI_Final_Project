## Architectural Decisions

1. **`metrics_summary` uses a typed `MetricClaim` model, not a free-text
   `dict[str, float]` or narrative string.** *Why:* the task explicitly
   asked for a typed/mechanical representation over a substring hack; a
   typed claim lets the guardrail reuse `verify_metric_in_experiments`
   directly instead of parsing narrative text for numbers.
2. **The "≥1 contract assumption referenced" rule reuses the existing
   `contract_dependencies` field rather than inventing a new one.** *Why:*
   the task explicitly said not to invent unrelated fields; §G.3 point 6
   lists exactly nine fields, and `contract_dependencies` is the field
   whose stated purpose (what the model depends on from the contract)
   already covers "references a contract assumption" as a special case —
   checked mechanically via exact set-membership against
   `contract.assumptions`.
3. **The model-card/evaluation-report Jinja2 renderer was NOT built.**
   *Why:* full evidentiary reasoning above (§5) — both are Crew 2's own
   agent artifacts (Phase 7), and Phase 5's scope text names Jinja2
   rendering explicitly only for EDA. Building it now would have been
   exactly the "pull Phase 7 work forward" this session's own instructions
   forbade.
4. **Reused `ml.evaluate.verify_metric_in_experiments` verbatim rather than
   writing a second lookup function.** *Why:* a second, textually similar
   but independently-written verification path is exactly the kind of
   quiet-divergence risk this project's whole "measured, not narrated"
   philosophy exists to prevent (§E.1 rule 5 applied by analogy).
