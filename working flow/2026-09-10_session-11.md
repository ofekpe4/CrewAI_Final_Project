## Results

**Task 1.3 — PASS.** Callback ordering verified against `1.15.20`.

### API

- **`Task(callback=...)` exists.** Field `callback: Optional[Callable[..., Any]]`,
  default `None`, description *"Callback to be executed after the task is completed."*
  (A string is accepted and coerced via `string_to_callable`.)
- **Invocation site** (`Task._execute_core`, source-confirmed): the callback is called
  **after** the guardrail loop has returned **and after** `self.output = task_output`,
  and **before** the `output_file` save, the `TaskCompletedEvent`, and `return
  task_output`. Call is `cb_result = self.callback(self.output)`; a plain return value
  is **discarded** — only `inspect.iscoroutine(cb_result)` is checked (a coroutine is
  run with `asyncio.run`). So a sync callback is invoked **synchronously and blocks**.
- **Crew loop** (`Crew._execute_tasks`, source-confirmed): non-async tasks run through
  `task_output = task.execute_sync(...)` inside a plain `for task in tasks:` loop.
  `execute_sync → _execute_core` runs the agent, the guardrail loop **and the
  callback** before returning; only then does the loop advance to the next task.

### Experiment A — event ordering

Observed event log (monotonic, one crew run, two sequential tasks):

```
 0  +  0.00 ms  task1_agent_llm_call
 1  +  2.73 ms  task1_callback_START
 2  +  2.84 ms  task1_callback_file_written
 3  +307.89 ms  task1_callback_FINISH
 4  +318.92 ms  task2_agent_llm_call
```

**`callback_finish` before `task2_agent_start`: YES** (event index 3 < 4).

### Experiment B — filesystem artifact

- artifact written by the callback (`open`/`write`/`flush`/`os.fsync`/`close`): **YES**.
- Task 2's agent, at the very start of its LLM call, saw the file: **YES**
  (`file_exists = True`).
- exact content verified: **YES** — Task 2 read `"written-by-task1-callback::42"`,
  byte-for-byte equal to what the callback wrote.

### Experiment C — blocking

- callback span ≈ **305 ms** (deliberate `time.sleep(0.30)` inside it).
- `callback_START → task2_agent_start` gap ≈ **316 ms** (> the sleep).
- **Task 2 started during the callback: NO.**
- **callback fully completed first: YES.** Execution is single-threaded and
  synchronous; the crew loop cannot advance while the callback is running.

### Experiment D — callback input / return

- exact input type: **`crewai.tasks.task_output.TaskOutput`** (`isinstance` True).
- attributes available in the callback: `agent`, `description`, `json_dict`, `name`,
  `output_format`, `pydantic`, `raw`, `summary`.
- `.pydantic` **is populated** when the callback runs (here `ToyNote(text='one',
  count=1)`, `output_format == OutputFormat.PYDANTIC`) — because the callback fires
  after `_export_output` / the guardrail loop. (Task 1.2 caveat still holds: *during*
  guardrail evaluation `.pydantic` is `None`; by callback time it is set on the success
  path.)
- **return value used by CrewAI: NO.** The callback returned
  `"CALLBACK_RETURN_SENTINEL"`; `crew_output.pydantic` was `ToyNote(text='two',
  count=2)` and `t1.output.raw` was unchanged. Return is discarded unless it is a
  coroutine.

### Experiment E — callback failure

Event log: `E_task1_agent_llm_call` → `E_task1_callback_START` → (nothing more).

- exception propagated to `kickoff()`: **YES** — as **`builtins.RuntimeError`** (the
  original type, message `"intentional callback failure (spike)"`). `_execute_core`
  catches, emits `TaskFailedEvent`, then `raise e`.
- Task 2 started after the failure: **NO** (`E_task2_agent_llm_call` never fired).
- Crew halted at Task 1: **YES**.

### Implications for Pattern A (evidence only — decision deferred)

The callback-timing dimension of Pattern A (§C.2.2) **holds** on `1.15.20`:
`Agent N → TaskOutput (validated) → sync Python callback → artifact flushed to disk →
Agent N+1 starts → Agent N+1 reads the fresh artifact` is exactly what Experiments
A+B+C show, and a callback exception fails the run visibly at task N (Experiment E),
which matches the Plan's "critical agent → fail visibly, no silent fallback" (§A9,
§D.1/§D.3). Still **not** enough to choose Pattern A over B: that also needs
`context=[task]` structured-context passing (Task 1.4) and `Literal` tool-signature
enforcement (Task 1.5).

### Proven vs inferred

- *Proven by execution:* callback runs after TaskOutput creation and fully finishes
  before the next sequential task's agent starts; it blocks the crew loop; a
  callback-written+fsynced file is visible with exact contents to the next task's
  agent; input is a `TaskOutput` with `.pydantic` populated; return value is ignored;
  a raising callback propagates the original exception out of `kickoff()`, halts the
  crew, and prevents task 2.
- *Inferred from source only:* the `crew.task_callback` second hook (only fires when
  set and `!= self.callback` — not exercised); coroutine callbacks run via
  `asyncio.run` (not exercised); behaviour with `async_execution=True` tasks (the loop
  has a separate `futures` path — out of scope, Plan uses `Process.sequential` sync).
