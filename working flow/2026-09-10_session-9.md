## Results

**Task 1.1 — PASS.** `output_pydantic` runtime behaviour is verified against `1.15.20`.

1. **Does `Task(output_pydantic=Model)` exist and work?** — **YES.** Field present,
   typed `type[pydantic.BaseModel] | None`. A crew with a task carrying
   `output_pydantic=ToyNote` runs and produces a structured object.
2. **Exact type exposed after a successful structured task** — the crew returns
   `crewai.crews.crew_output.CrewOutput`; its `.pydantic` attribute is a **real instance
   of the supplied model class** (`isinstance(out.pydantic, ToyNote)` → `True`,
   `ToyNote(text='hello spike', count=7)`). Per-task, `task.output` is a
   `crewai.tasks.task_output.TaskOutput` with the same instance on `.pydantic`.
3. **Where the validated object is available** — `crew_output.pydantic` (last task) **and**
   `task.output.pydantic`. Also `task.output.raw` (the raw JSON string),
   `task.output.output_format == OutputFormat.PYDANTIC`. `.json_dict` stays `None` when
   `output_pydantic` (not `output_json`) is used.
4. **Valid output** — task and crew complete; `.pydantic` is a schema-valid model
   instance; `.count` is a real `int`. **Coercion probe (A2):** raw `{"count": "7"}`
   (string) yields `count == 7` as `int` — i.e. **pydantic v2 default (lax) coercion
   applies**, not strict validation. (Design note for Task 1.2 guardrails: string→int /
   truthy→bool coercions will pass `output_pydantic` silently.)
5. **Invalid output** — the schema is enforced hard:
   - **B — uncoercible type** `{"count": "not-a-number"}` → `crew.kickoff()` **raises
     `pydantic.ValidationError`** (`error_count == 1`, `type='int_parsing'`,
     `loc=('count',)`). Propagates straight out of `kickoff()`.
   - **B2 — missing required field** `{"text": "only text"}` → **raises
     `pydantic_core.ValidationError`**: `count Field required [type=missing]`. Fake-LLM
     call count stayed at **1** → no repair/re-ask round-trip on this path (matches
     source: `handle_partial_json` does `except ValidationError: raise`).
   - **Invalid data cannot escape as a "valid" Pydantic object.** `.pydantic` is only
     ever populated by `model.model_validate[_json]`; the only non-raising failure mode
     (no JSON block at all → `convert_with_instructions` exhausts retries) returns the
     **raw string** and leaves `.pydantic = None` — never a half-built model.
6. **Who enforces the schema** — in this configuration (plain-text LLM output, no
   guardrail, `supports_function_calling=False`): **a deterministic parsing/validation
   step inside CrewAI's `Task`**, namely `Task._export_output → convert_to_model →
   validate_model → pydantic `model.model_validate_json`**. It is *pydantic* doing the
   validation, *invoked by CrewAI*, **after** the agent produced text. It is **not** the
   LLM's own structured-output mechanism here. (When a real function-calling LLM returns
   a `BaseModel` directly via `response_model`, `_execute_core` takes the
   `isinstance(result, BaseModel)` branch and trusts that object as-is — still a
   pydantic-constructed instance, so the "valid instance or raise" guarantee holds either
   way.)
7. **API names/signatures actually present in `1.15.20`** —
   `Task(output_pydantic=<BaseModel subclass>)`; `Task.output` → `TaskOutput`;
   `TaskOutput.pydantic / .raw / .json_dict / .output_format`;
   `OutputFormat.{RAW,JSON,PYDANTIC}`; `Crew.kickoff()` → `CrewOutput`;
   `CrewOutput.pydantic`; `crewai.BaseLLM.call(messages, tools=None, callbacks=None,
   available_functions=None, from_task=None, from_agent=None, response_model=None)`.

**Proven vs inferred:**
- *Proven by execution:* existence and effect of `output_pydantic`; returned types
  (`CrewOutput` / `TaskOutput` / model instance); location of the validated object;
  valid path; default coercion; invalid path raises `ValidationError` out of `kickoff()`;
  no silent escape of invalid data; enforcement is a post-hoc pydantic step for
  plain-text output.
- *Inferred from source only (not exercised this session):* the native
  `isinstance(result, BaseModel)` branch (needs a real function-calling LLM); the
  `convert_with_instructions` second-LLM-call repair path (needs a real LLM);
  interaction of `output_pydantic` with `guardrail` / `max_retries` (explicitly Task 1.2).
