### Deviation encountered and corrected (reported per CLAUDE.md "Verification")

The first skeleton-creation command used a shell `for` loop over an unquoted multi-line
variable (`for d in $LEAF_DIRS`). The Bash tool's shell is **zsh**, which — unlike bash —
does **not** word-split unquoted parameter expansions. The loop therefore ran once with
the entire newline-containing string as a single value, and `mkdir -p` / `touch` created
one malformed directory whose name began with a newline
(`$'\nconfig/narrative_fallbacks\nsrc/...'`). No intended directory was created; no
existing file was touched; the damage was one stray untracked tree at the repo root.

Remediation: identified the directory by its exact bytes (`0a 63 6f 6e 66 69 67` =
`\nconfig`), removed it with `rm -rf -- "<that exact name>"`, re-verified the repo root
was clean, then recreated the skeleton with an explicit, individually-quoted argument
list to `mkdir -p` and a quoted `for` list for the `.gitkeep` files. Second attempt was
clean. Nothing outside the stray directory was ever affected, and it never entered Git
(never committed, never `git add`-ed before removal).

## Architectural Decisions

- **`.gitkeep` in empty leaf directories only.** Task 0.7 = "directory skeleton" (Plan §T
  Phase 0 step 9, "שלד תיקיות"). The Plan's §L filenames (`pipeline_flow.py`,
  `schema.py`, `agents.yaml`, `style.css`, …) belong to their own later tasks/phases, so
  **no named stub files were created** — only `.gitkeep`. Placeholder goes in the deepest
  empty directory of each branch; parent directories are kept by their child's
  placeholder.
- **`runs/` and `logs/` get no placeholder.** `.gitignore` excludes them wholesale; they
  are runtime output directories and are auto-created when the pipeline runs. Creating a
  tracked file inside a fully-ignored directory would be misleading.
- **`artifacts/**` IS tracked** (empty subdirs get `.gitkeep`), per Plan §K ("ארטיפקטים
  בגיט"). Only the artifact *output files* are absent; the directory shape is in place.
- **Deferred, on purpose (not part of Task 0.7):** `README.md` (Plan §T Phase 0 step 11),
  `requirements-dev.txt` (dev deps, later + explicitly deferred in Task 0.5),
  `pyproject.toml` and `Makefile` (no Phase 0 step assigns them; `Makefile` first appears
  in Phase 8 scope), `data/README.md` (Phase 2 scope), and every `.py`/`.yaml`/`.css`/
  `.j2` implementation file (Tasks 0.8+ and Phases 1–11). No `__init__.py` files were
  created — §L does not list them and packaging is not yet configured; they will be added
  when packaging is set up.
