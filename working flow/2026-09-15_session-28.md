### 3 — Two real `crewai==1.15.20` Flow-API findings (documented in
`docs/architecture.md`'s new Phase 8 addendum, not just this file)

1. `Flow[PipelineState]`'s generic specialization narrows the
   `initial_state` constructor field to `type[T]` only — a `BaseModel`
   *instance* (`HarborValeFlow(initial_state=PipelineState(...))`) raises
   `pydantic_core`'s `is_subclass_of` error, even though the runtime's own
   `_create_initial_state` has a dead branch for it. Fixed by giving
   `HarborValeFlow.__init__` plain kwargs (`fault_injection`,
   `validate_only`, `replay_plans`, `dataset_path`, `llm`) that assign onto
   `self.state` right after `super().__init__()` — verified reliable.
2. `Flow.plot(filename=...)` always writes into a fresh OS temp directory;
   `filename` is basename-only, never a destination path (three sibling
   files: `.html` + `_style.css` + `_script.js`, cross-referenced by
   relative path). `flow.generate_flow_diagram()` copies all three into
   `docs/` so the artifact is committable and self-contained — documented
   honestly rather than silently worked around.
3. The framework requires every Flow state model to declare an `id` field
   (`"Flow state model must have an 'id' field"`) — `PipelineState.id` is
   that framework-required field, kept fully separate from the Plan's own
   `run_id` (the field every log line/artifact/report is keyed by).

## Architectural Decisions

1. **`HarborValeFlow.__init__` takes plain kwargs, not
   `initial_state=PipelineState(...)`.** *Why:* the installed
   `crewai==1.15.20`'s `Flow[T]` specialization rejects a `BaseModel`
   instance for `initial_state` (§3 finding 1) — verified, not guessed;
   assigning onto `self.state` post-`super().__init__()` is the reliable,
   tested path.
2. **`experiments.json`'s path is derived as a sibling of
   `result.evaluation_report_md`, never a hardcoded `EXPERIMENTS_JSON`
   constant**, inside `verify_crew2_outputs`. *Why:* makes the same
   verification code correct whether `result` came from a real production
   run, a replay workspace, or a test's own temp directory — removed a
   `state.replay_plans`-branching special case in the same change.
3. **Only `scale_change` is wired to a Flow injection point**, not every
   `demo/fault_injection.py` helper. *Why:* it is the one §O.3/§P.1
   MANDATORY scenario this Phase must prove end-to-end; the rest remain
   Phase 4-tested, unwired functions, exactly as the Plan scopes them
   (Phase 10 owns the full failure catalog).
4. **`--replay-plans` + `--inject-failure` IS an allowed CLI combination**
   (the only two-flag combination that is). *Why:* Gate 8.15 explicitly
   wants the fault route proved "through mocked/replay plans" without
   spending an additional live LLM pipeline — this combination is the
   literal mechanism for that, and it is fully exercised offline in
   `test_fault_injection_ordering`'s sibling reasoning (the offline test
   uses a mocked Crew 1 instead of `--replay-plans` specifically because
   the real stored Crew-1 plans did not exist yet at the point that test
   was written in this same session — see Known Issues).
5. **`PipelineState.model_config = ConfigDict(validate_assignment=True)`.**
   *Why:* the state is mutated in place by every one of twelve Flow nodes
   over one run's lifetime; validating on assignment (not just
   construction) catches a typo'd status/failure_category literal at the
   exact node that introduced it — caught a real test bug during this same
   session (an invalid-status test had silently passed before this was
   added).
