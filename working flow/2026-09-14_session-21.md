## Architectural Decisions

1. **Guardrail context parameters default to `None`, never raise, return a
   clear wiring-error message if actually `None`.** *Why:* the only way to
   keep a guardrail needing external context (`profile`, `contract`,
   `eda_stats`) constructible as a bare `Task(guardrail=fn)`, given the
   newly-verified "exactly one REQUIRED parameter" rule — discovered
   empirically this session, documented in `docs/architecture.md`.
2. **`FeaturePlan`'s derivation vocabulary is deliberately just `"ratio"`.**
   *Why:* the task explicitly warned against inventing a scripting
   language; a single, safe, well-understood derivation (with an explicit
   zero-denominator policy) is enough to prove the mechanism without
   opening an arbitrary-expression door.
3. **The hardcoded `CleaningPlan` does NOT touch the tri-state service
   columns or `senior_citizen`'s encoding.** *Why:* the already-merged
   Phase 3 `ContractDraft` treats both as legitimate declared states (a
   3-value closed domain; an explicit int64 dtype constraint) — cleaning
   them away here would silently contradict Phase 2/3's own conclusions,
   which this task explicitly forbids doing without approval.
4. **`ExperimentPlan`'s estimator enum is the Plan's actual 3, not the
   prompt's paraphrased 4 (`decision_tree` excluded).** *Why:*
   `PROJECT_PLAN.md` §G.2 itself names exactly `logistic_regression`,
   `random_forest`, `gradient_boosting` as "3 וריאציות (קפוא בכוונה)"; the
   accelerated-workflow prompt's "such as ... decision_tree" list is not
   the Plan itself. Followed the Plan; recorded the discrepancy here
   rather than silently reconciling it or stopping to ask (not a real
   contradiction requiring a stop — just a prompt imprecision).
5. **`model.joblib`/figure byte-identity is checked, not assumed.** *Why:*
   explicit task instruction not to claim byte-identical joblib files
   without proof; ran the actual comparison and reported the real,
   verified result, with the caveat about single-threaded determinism
   spelled out rather than presented as an unconditional guarantee.
6. **`access/handoff.py` drops `from __future__ import annotations`.**
   *Why:* discovered via a failing test that stringizes `HandoffName`'s
   `Literal` — a real hazard for Phase 6+'s `@tool` wrapping of this exact
   function, the same class of risk Sessions 17–18 documented for
   guardrail return annotations, here on an argument annotation instead.
7. **Templates renamed from `*.j2` to their real extensions.** *Why:*
   discovered via a failing test that Jinja2's `select_autoescape` matches
   by the template's own last extension — `.j2` silently disabled HTML
   autoescaping, a real (if not yet exploited) injection risk in
   `eda_report.html`.
